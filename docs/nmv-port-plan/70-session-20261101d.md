## 2. Double Trouble：一条链式赋值炸掉整个 onCreatePost

### 2.1 日志证据

```
09:48:51 HS ERROR doubletrouble:279: Invalid field:useRenderTexture
09:48:51 script: ERROR: doubletrouble:279: Invalid field:useRenderTexture
09:48:51 PS onCreatePost dispatched
09:48:51 script: ERROR: doubletrouble:496: Invalid access to field update      ← 之后每帧
```

`warehouse/doubletrouble.hx:279`：

```haxe
boyfriend.useRenderTexture = gf.useRenderTexture = dad.useRenderTexture = pet.useRenderTexture = bfIntro.useRenderTexture = true;
```

HScript 的 `set` 是 `Reflect.setProperty`，**写缺失字段在 hxcpp 上会抛** `Invalid field:xxx`
（读不会，见 §3.1）。链式赋值从右往左，第一个就炸在 `bfIntro`（类型 `FunkinSprite`）——
`Character` 和 `PetStub` 早就有这个兼容字段，唯独 `FunkinSprite` 漏了。

于是 `onCreatePost` 在 279 行中断，后面全部没跑：

- `red = new Character(-420, -390, 'doubleTroubleRed')`（375 行）→ **`red` 恒 null**
- `redElement` / `dad.library.getSymbol('red placeholder')`（404 行）→ 没跑
- 灯光 `lightoverlay`×2、`camGame.filters = [ShaderFilter(rainShader)]`、
  `greenShader.attachedSprite` 等、最后 `lightningStuff(0)` → 全没跑

而 `onUpdate`（496 行 `red.update(elapsed)`）和 `onBeatHit`（547 行 `red.onBeatHit(curBeat)`）、
`opponentNoteHitPre`（537 行 `red.animation.name`）照旧每帧/每拍触发 → 就是刷屏的 4129 / 20 / 22 行。

### 2.2 改动

- `source/nmv/objects/FunkinSprite.hx`：`useRenderTexture` + `_renderTextureDirty`（都是无渲染语义的兼容字段）。
- `source/objects/Character.hx`：`_renderTextureDirty`（378 行在 `onFrameChange` 回调里逐帧写它）。
- `source/nmv/scripts/InterpEx.hx`：`f == 'name'` 且宿主是 atlas `Character` 时返回
  `getAnimationName()`。原因：atlas 角色的标准 `animation` 控制器 `curAnim` 恒 null，`name` 得 null，
  而 Haxe 4.3 的 `StringTools.startsWith` 在 **cpp 分支没有 null 保护**
  （`return (s.length >= start.length && ...)`）→ `startsWith(null,'sing')` 裸 NPE，
  doubletrouble:537 每条 `Opponent 2 Sing` 音符一次。NMV 那边 `Character.animation` 就是 animate
  控制器、`name` 恒有值，这里按同一语义补上。

### 2.3 已知遗留（本次没做）

`dad.library`（NMV 的 `FlxAnimateFrames`）仍然**不存在** → 该字段读到 null，
`if (dad.library != null)` 直接跳过。所以 `red` 虽然被创建、会唱歌、会被 `note.owner = red`
指派音符，但**不会被合成进 dad 的绘制树 → 看不见**。

真要补，工作量和 66 号那种"改锚点"不是一个量级：需要把 MaybeMaru 的
`animate.internal.elements.FlxSpriteElement`（把任意 FlxSprite 当元素画进符号树、
`applyObjectTransform` 里用父矩阵重定位）+ `FlxAnimateFrames.getSymbol` /
`Timeline.layers` / `Frame.elements` / `Frame.add` 一整套搬进 Dot-Stuff 的绘制树。
`source/nmv/objects/AnimateElementShim.hx` 现在只是个"字段可写、不联动显示树"的空壳（charles.hx 用）。

## 3. Torture：`Conductor.crotchet` 缺失 → 时长为 0 的补间是"死"补间

### 3.1 先记住两条 HScript 行为

| 操作 | 缺失字段时 |
|---|---|
| **读** `obj.field` | `Reflect.getProperty` **静默返回 null**（不报错） |
| **写** `obj.field = v` | hxcpp 抛 `Invalid field:xxx`（除非 `InterpEx.set` 特判） |
| **调** `null.method()` | 抛 `Invalid access to field method` |

所以"读错字段名"是**最隐蔽**的一类移植 bug：不报错，只是后续数值全变 0/null。

### 3.2 拼写差异

| NMV（`funkin/backend/Conductor.hx:18`） | FE（`backend/Conductor.hx:17`） |
|---|---|
| `crotchet` | `crochet` |
| `stepCrotchet` | `stepCrochet` |

语料里 `Conductor.crotchet` **31 处**、`Conductor.stepCrotchet` **7 处**（`.hx`）。
FE 没有这两个名字 → 全部读到 null。

### 3.3 为什么 null 会变成"永久黑屏"

`warehouse.hx`（Torture 的舞台，`data/stages/warehouse.hx`）：

```haxe
// onCreatePost:88
startDark = new flixel.system.FlxBGSprite();
startDark.color = FlxColor.BLACK;
startDark.zIndex = 5;          // 盖满全屏
add(startDark);
...
// onCreatePost:93  ziffy 开场动画也 zIndex = 5，后 add → 画在黑幕之上 ✓"开局有动画"
...
// onEvent 'start'（谱面 @10322ms）
FlxTween.tween(startDark, {alpha: 0}, (Conductor.crotchet * 28) / 1000, {...});
```

`Conductor.crotchet` = null → `(null * 28) / 1000` = **0** → 补间时长为 0。
flixel 6.2 `FlxTween.hx:675`：

```haxe
public function start():FlxTween {
    ...
    if (duration == 0) {
        active = false;      // ← 直接失活
        return this;
    }
    ...
}
```

→ 补间**永不 update、alpha 永远是 1、`onComplete` 永不触发**（`startDark.destroy()` 也不会执行）。
`FlxBGSprite.draw()` 是先 `_matrix.scale(camera.viewWidth+1, ...)` 铺满相机再 `drawPixels`，
`colorTransform` 里 RGB 乘 0 = 纯黑 —— 于是**从开场动画结束一直到退歌都是黑的**。

同一根因的连带症状（这些歌以后会一起变正常）：

- `attack.hx:249` / `chef.hx:82` / `greenhouse.hx:219` / `polus.hx:96` / `pretender.hx:126` /
  `victory.hx:61` 的 `fakeStartTimer = new FlxTimer().start((Conductor.crotchet / 1000) / playbackRate, ...)`
  → 时长 0（假倒计时被瞬间跳过）
- `warehouse.hx` 的 `saw`（刀片下压 + camGame 缩放）、`bye`（health 补间）、`rozebud`（zoom）全部无效

### 3.4 改动

`source/backend/Conductor.hx`：

```haxe
public static var crotchet:Float = crochet;         // NMV 拼法
public static var stepCrotchet:Float = stepCrochet;

public static function set_bpm(newBPM:Float):Float {
    bpm = newBPM;
    crochet = calculateCrochet(bpm);
    stepCrochet = crochet / 4;
    crotchet = crochet;          // 唯一赋值点，两套拼写同步
    stepCrotchet = stepCrochet;
    ...
}
```

（用普通 static var 而不是 `(get, never)` 属性：hxcpp 对**静态属性**的 `Reflect` 反射不保证走
getter，而 `crotchet` 还要供 Lua `getPropertyFromClass` 用，普通字段最稳。）

## 5. 教训（写进长期记忆）

- **HScript 读缺失字段是静默 null**。移植期"脚本不报错但数值全 0"优先怀疑**字段名拼写**
  （NMV vs Psych 命名差异），别先怀疑逻辑。
- **flixel 的 `FlxTween` 时长为 0 = 补间直接失活**（不是"立刻完成"）。
  脚本里所有 `FlxTween.tween(x, {...}, 计算出的时长)` 都要确保时长 > 0。
- 链式赋值 `a.f = b.f = c.f = v` 在 HScript 上从右往左，**最右边那个字段缺失就会整条炸掉**。
  移植兼容字段要么整类补齐，要么一个都别留。

### 7.1 死亡特殊音效：json 只读了 1/3

NMV `Character.hx:200-202` 读三个键，**注意 `intial` 是 mod 侧的错拼**：

| json 键 | 端口字段 | 消费点 |
|---|---|---|
| `gameover_intial_sound`（少一个 i） | `gameoverInitialDeathSound` | `deathSoundName` → `Paths.sound()` |
| `gameover_loop_sound` | `gameoverLoopDeathSound` | `loopSoundName` → `Paths.music()` |
| `gameover_confirm_sound` | `gameoverConfirmDeathSound` | `endSoundName` → `Paths.music()` |

移植端此前**只读了 loop** → 首音效/确认音永远是默认 `fnf_loss_sfx` / `gameOverEnd`。
语料 13 个角色带 `gameover_intial_sound`，且都指到真实文件：
`stage/ejected_death`（bf-fall）、`stage/defeat_kill_sfx`、`stage/defeat_kill_ballz_sfx`、
`stage/stickbf_Death`、`stage/fnf_loss_sfx-pixel`、`stage/fnf_loss_sfx-pico`、`stage/idk_death`。

取值来源仍是**玩家角色**（NMV `new(character)` 传的是 `playerStrums.owner`），
不是 `gameover_character` 那个死亡角色 —— 例：ejected 用 `bf-fall` 的 `stage/ejected_death`，

### 7.3 turbulence 开局一个错：`Invalid field:rotatableOffsets`

```
10:07:47 HS ERROR turbulence:102: Invalid field:rotatableOffsets
```

`turbulence.hx:102`（`evil()` 里，把 bf 摆成被爪子抓住的姿态）：

```haxe
boyfriend.legacyOffset = boyfriend.rotatableOffsets = false;   // ← 写路径，缺字段抛异常
```

`legacyOffset` 端口有、`rotatableOffsets` 没有 → 整段 `evil()` 从这里中断，后面
`setPosition(claw)` / `angle = -90` / 换向重命名全没跑。

修：`Character` 补 `rotatableOffsets:Bool = true`（NMV `FunkinSprite.hx:44`，
`setOffsets` 里 `if (rotatableOffsets) point.rotateByDegrees(angle)`）。
端口**只留字段不实现旋转**：偏移是轴对齐的 `offset`，旋转要连带改 `NmvAtlasAnchor` 口径，
风险大于收益；而 bf 的 `animOffsets` 全是 0，旋不旋转本来没差别。

**副作用（预期内）**：`evil()` 以前整段没跑，现在会真的执行 —— bf 会被摆到 claw(930,800)、
`angle = -90`、并做 `singUP↔singLEFT` 之类的换向重命名。
但 `if (boyfriend.animateAtlas != null)` 那一大块（用 NMV 的
`Timeline.getWholeBounds/getBounds` 校正 size/origin/x/y）在端口里读到的 `animateAtlas` 是 null，
**整块跳过** → 末尾两行 `x += (height - width)*.5 + 50` / `y += (claw.height - width*scale)*.5 + 10`
在 atlas 角色上会用到退化的 `width/height`（atlas 角色只有 1×1 的合成帧）→ 落点可能偏几十像素。
如果实测明显歪，再单独处理（要么给 atlas 角色补一套 `width/height`，要么在 `evil()` 层面兜）。
