## 2. bf-fall：为什么上一轮"标签优先改锚点"必然无效

上一轮（66 号 §7）的做法是：`NmvAtlasAnchor.resolveSymbol` 发现 `base` 是主符号帧标签就返回主符号。
两处都错：

### 2.1 判据永远 false

`atlas.anim.getFrameLabel(name)` → `curSymbol.getFrameLabel(name)`（`FlxAnim.hx:576`），
**走的是当前播放符号**。播放 `singRIGHT-loop` 时 `curSymbol` 是包装符号
`@animations/right@singRIGHT-loop`，它没有任何帧标签 → 恒 null。

日志铁证（09:39:09，构建于 09:36，改动已生效）：

```
nmv bounds characters/bf/bfFly|animations/right via=singRIGHT-loop frames=18 x=-20 y=-5 w=466 h=494
```

仍是子符号。

### 2.2 就算判对，只改锚点会把画面推得更远

锚点（`_bounds`）和内容必须**同源**。看 `bfFly/Animation.json` 主时间线的
`animations/right` 段（`I=304 DU=17`，只有一个关键帧）：

```json
{"SI": {"SN": "animations/right", "FF": 0, "MX": [1,0,0,1,-211.6,-241.05]}}
```

主时间线帧 304 画的是**子符号实例 + 打包位移 (-211.6,-241.05)**。所以：

- 走主符号：屏幕位置 = `char + json + (子坐标 + t) - 主包围盒`，`t = (-211.6,-241.05)`
- 走子符号：屏幕位置 = `char + json + 子坐标 - 子包围盒`

两者要相等，必须 `t = 主包围盒 - 子包围盒`——实际 `主-子 = (-663,-501)`，`t = (-211.6,-241.05)`，
**差 451/260 像素**。也就是说：只把锚点换成主符号、内容仍画子符号，会比现在再偏 451/260。
"锚点差 663/501"这个数字本身没有意义，它只是两条时间线的包围盒差。

## 3. 正解：注册端对齐 NMV

参考引擎 `FunkinSprite.hx:243-252`：

```haxe
public function addAnimByIndices(name, prefix, indices, ...) {
    if (library != null && anim.findFrameLabelIndices(prefix).length > 0)
        anim.addByFrameLabelIndices(name, prefix, indices, ...);   // timeline = 主时间线
    else if (checkLibraryForSymbol(library, prefix))
        anim.addBySymbolIndices(name, prefix, indices, ...);       // timeline = 子符号
    ...
}
```

而 `FlxAnimateController.addByFrameLabelIndices`（MaybeMaru 库 105-135 行）里
**`indices` 是标签段内的相对序号**：`useableFrames.push(foundFrames[index])`，越界直接丢。

移植端此前把 indices 排在标签前面（为 gf 的 `danceLeft/danceRight`），于是
`bf-fall` 的 `*-loop` 掉进子符号。这次改成 NMV 顺序。

### 3.1 改动

`source/objects/Character.hx` 注册优先级（现在逐字对齐 NMV）：

1. 有 indices 且 `name` 是根时间线帧标签 → **标签段 + indices**（新增 `addFromFrameLabelIndices`）
2. 有 indices 但没标签 → 符号 indices（子符号）
3. 无 indices 且有标签 → 帧标签整段
4. 精确符号 → 5. 帧标签兜底 → 6. 前缀兜底

`source/nmv/utils/NmvAtlasAnchor.hx`：删掉"标签优先"分支（`mainSymbolOf` / `isFrameLabel`），
`resolveSymbol` 回到"包装符号拆回源符号"。理由写在代码注释里，防止下一个对话再加一次。

### 3.2 影响面（全语料实测，非估算）

144 条带 `indices` 的动画里，**76 条** `name` 同时是主符号帧标签 → 这次会改走主时间线。
按角色分：`bf-fall`（7）、`bf`（1，`idle-scared`）、全部 gf 变体（`danceLeft/danceRight/sad`）、
`maroon`/`maroonplayable*`、`upboy`/`upgirl`、`charles`、`nenolobby`、`yellow`、`amongGf`、`bfsusreal`。

**标签段长度是否够 indices**：72/76 够；只有 gf 的 `danceLeft` 写了个 `30`、而
`GF Dancing Beat` 段长正好 30（0..29）→ 第 0 项被丢，播 15 帧而不是 16 帧。
NMV 同样是丢，所以这不是回归。

### 3.3 为什么 `bf`（BOYFRIEND）不受影响

`bf` 只有 `idle-scared` 带 indices。上一轮被回退的 `label-fallback` 是"**无 indices** 的
name 不是标签时再拿 anim 名查一次"——那条分支这次没动，`bf` 的 idle 仍走子符号。✓

## 4. 特殊死亡动画

### 4.1 证据

09:40:47（用户当时在跑 Ejected，player1 = `bf-fall`）的 `bread.log`：

```
char[bf-dead] atlas begin characters/BOYFRIEND_DEAD
char[bf-dead] anim firstDeath label[BF dies]
```

`bf-fall.json` 明确写着 `"gameover_character": "bf-fall-dead"`，而引擎去加载了通用 `bf-dead`。

### 4.2 根因

`GameOverSubstate.resetVariables()` 只读 `SONG.gameOverChar / gameOverSound / gameOverLoop / gameOverEnd`。
NMV 语料 **218 个谱面里没有任何 gameOver\* 字段**（全在角色 json 的 `gameover_character` 上，
47 个角色带这个字段）。

而且那段"从 `PlayState.instance.boyfriend` 读三个死亡音效"的代码是**死代码**：
`resetVariables()` 在 `PlayState.create:923` 调用，角色到 `1048-1062` 才创建 → boyfriend 恒 null。

### 4.3 改法

照抄 NMV `GameOverSubstate.hx:108-118`，全部挪进构造函数 `new(playStateBoyfriend)`：

- `characterName = character.gameoverCharacter`（谱面显式写了 gameOverChar 时让谱面优先，
  保住 FE 自家 mod 的既有行为；NMV 谱面从不写 → 等价于 NMV 的"角色优先"）
- `deathSoundName / loopSoundName / endSoundName` 三个也从角色取（resetVariables 里只留谱面字段）
- 新增面包屑 `gameover char=<名字> from=<玩家角色>`

例：`bf-fall` → `bf-fall-dead`（**同一张图集** `characters/bf/bfFly`，死亡动画就是主时间线上的
`animations/dead 0START / 1MID / 2END` 三条帧标签，119/33/33 帧）；
`bf-running` → `bf-running-death`；`bf-defeat-normal/scared` → `bf-defeat-dead`；`bf-ghost` → `bf-ghost-dead`…
