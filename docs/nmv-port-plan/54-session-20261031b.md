## 1. 坐标纠正延迟：idle@0 门读错控制器（永不命中 → 全走 480 帧超时）

### 面包屑实证（crash/bread.log）

- 10-30 23:13–23:31（旧构建，首绘采样无门控）：`nmv anchor bf dx=288 dy=-200`、
  `gf -147,-333`、`black -4,-3` —— 旧正确基准值。
- 10-31 06:22–06:26（批次 3 新构建）：**全部 `nmv anchor timeout`**，且值离群：
  bf `88,-321`（应 288,-200）、gf `-362,-453`（应 -147,-333）、gf-fall `-756,-1026`、
  yellow `-636,-418`。三个角色同一秒 timeout = 生成后 480 绘制帧（60fps ≈ 8 秒）
  齐齐到点，随后按"当前帧"采样 → 采到 sing/过渡帧的离群 content min。

### 根因

门的判定读的是 **FE 的 `animation.curAnim`**：

```haxe
final curAnim = animation.curAnim;              // atlas 角色恒为 null！
final animName = (curAnim != null) ? curAnim.name : null;
final idleHit = (animName != null && curAnim.curFrame == 0) && ...;
```

atlas 角色的动画全程走 `atlas.anim.play(...)`（`playAnim` 的 atlas 分支，Character.hx:566），
FE 的 `animation` 控制器从不被驱动 → `animName` 恒 null → `idleHit` 恒 false →
每个角色都等满 `NMV_ANCHOR_MAX_DRAWS`(480) 帧才在超时分支采样。即"开局约 8 秒后才纠正"，
且超时采样的帧不是 idle@0，值本身也不对。

### 修法（Character.captureNmvAnchor）

- 动画名：读 `getAnimationName()`（= `playAnim` 记录的 `_lastPlayedAnimation`，atlas 路径
  每次播放都会写）；
- 帧号：读 `atlas.anim.curFrame`（fork 的 getter = `curSymbol.curFrame`，动画 force 播放时
  置 0，循环回卷也归 0）。
- 关键保证：Character 构造器尾部 `dance()`（Character.hx:207）→ 生成即播 idle 系动画@0 帧
  → **门修好后首绘就应命中**，延迟应为 0。缓存命中路径（同图集第二个实例）本来就是
  首绘即套用，不受门影响。
- 480 帧超时保留作兜底（永不跳舞的角色退回首绘采样 = NMV 首绘语义）。

### 下轮实测基准（对照 23:13 旧正确值）

|---|---|---|
| bf | 288,-200 | 88,-321 |
| gf | -147,-333 | -362,-453 |
| black | -4,-3 | （06:26 blackdk -91,-109，非同图集） |

面包屑应出现 `nmv anchor idle <名>`（而非 timeout），且开局首绘即打点、无 ~8 秒延迟。

### 4b. 超时任意帧采样回退（Character.captureNmvAnchor）

门语义复核（读 fork 源码后确认成立）：`addBySymbolIndices` 会建**合成符号**
（每个 index 一个 keyframe、`firstFrame=i`），注册动画播放时 `curSymbol`=合成符号 →
`atlas.anim.curFrame` 就是"动画内帧号"，`==0` = 动画首帧内容 ✓（含 gf 类 indexed
danceLeft/danceRight；exact-symbol 路径裸帧 0 同义）。
**回退点**：480 帧超时不再"任意帧采样"——非 idle@0 帧的 content min 不是锚点

（nmvAnchorReady=true、dx/dy=0）+ 面包屑 `nmv anchor skip <名>`，角色保持未补偿。
门本身（idle 系@0）+ 首绘快速路径 + 图集缓存 + viewMargin 全部保留。

### 4c. 镜头"偏左上"根因：cutscene 里 followLerp 被每帧归零

doubletrouble.hx intro（inCutscene=true 全程 ~12s）：
`FlxG.camera.followLerp = 1/20` + `FlxTween.tween(camFollow,{2370,1300},5.3)` +
`FlxTween.tween(camGame,{zoom:.7},15)`。FE update 的 `else FlxG.camera.followLerp = 0`

camTween 接力从 stale 位置起滑 → 视野停在左上区域。
NMV PlayState:1915 只在 `cameraLerping && !inCutscene` 时赋 0.04、**从不归零**
（cameraLerping 默认 true、无置 false 点）。
修：update 的 else 分支只在 `paused || NMVContentData.currentMod == null` 时归零

## 5. 逐动画锚点（用户实测 bf/red idle 对了、sing 偏 → 机制实证 + 重构）

### 机制实证（读 MaybeMaru flixel-animate 源码，D:.haxelib/flixel-animate/git）

- `FlxAnimate.drawAnimate`：`matrix.translate(-timeline._bounds)` **无条件**（216-217 行只
  看 renderTexture 分支；RT 路径 249 行同样平移）。
- `Timeline.refresh()`：`_bounds = getWholeBounds(false, ...)` = 该 timeline 的整条包围盒。
- **NMV 播放动画时 timeline = 当前符号自己的时间线** → 每个动画按"该符号整条时间轴
  包围盒左上角"钉位 = **逐动画常量**。
- 批次 3 推翻包围盒模型时看的是 `prepareDrawMatrix`（确实被 applyStageMatrix 门控不走），
  漏了 drawAnimate 里这个无条件平移。单常量模型下 idle 对了 sing 必偏 = 用户症状。
- 旁证：删除的确定性计算给 bf -212,-201 ≠ 实测 288,-200 —— 因为正确值是 **idle 符号
  自己的**包围盒角，不是根时间线的。两侧 animate 库不同（NMV=MaybeMaru 1.5.0，
  port=Dot-Stuff 4.0.0）就是这个平移差异的来源。

### 实现（Character.hx 重构）

- 字段换 `nmvAnimAnchors:Map<动画|翻转态, FlxPoint>` + `nmvAnchorDead`（skip-all）。
- 首锚门不变：等 idle 系@0（构造器 dance() 保证首绘命中），480 帧超时**弃用补偿**
  （`nmv anchor skip`，不喷任意帧垃圾值）。
- **逐动画采样**：其余动画各自 frame 0 首绘时采（playAnim 强制从 0 播 → 切动画首绘即
  命中；过帧等循环回卷补采），采样后立即重设 offset（set 不是 +=）。
- **缓存键 = 图集路径|动画名|渲染翻转态**（red 玩家/对手侧翻转不同各采各的），
  跨实例复用；未采样的动画回退 idle 系锚点。
- `nmvApplyOffset`：offset = json 偏移(翻转修正) + 当前动画锚点 —— playAnim 与采样共用
  一份镜像修正逻辑（原来 playAnim 里那段）。
- 面包屑格式改为 `nmv anchor <动画名> <角色> dx=.. dy=..`（idle 采样即 `nmv anchor idle bf`，
  兼容旧基准 grep）。

## 6. 第三次重做：确定性逐符号包围盒（嵌入角色、运行时零采样）

### 逐动画 frame0 实测版的三个实测问题（用户反馈）

1. **实时应用感/飘逸**：playAnim 先套 idle 兜底锚、首绘再采本动画锚 → 每次切动画
   两次跳。
2. **gf 逐拍上下跳（y）**：danceLeft/danceRight 各自 frame0 contentMin.y 不同
   （摆胯），逐拍换锚 = 跳动。
3. **角色随机跨场景漂移**：实测值含实例 scale（多K 缩放/不同谱面同角色不同 scale），
   缓存键不含 scale → 跨实例错配。

### 决定性验证（MaybeMaru 控制器）

`FlxAnimateController:359 _animate.timeline = curAnim.timeline` —— **播放即切时间线**
（符号动画=符号自己的 timeline；indices/label=合成 timeline）。drawAnimate 的
`translate(-timeline._bounds)` 吃的就是它 → 逐动画常量，机制板上钉钉。

### 实现（新 nmv/utils/NmvAtlasBounds.hx + Character.hx 换接）

- **确定性计算**：从已解析 Dot-Stuff 对象树按 NMV 同数学算"该动画符号整条时间轴
  包围盒"，不渲染、无运行时采样。复用批次 3 删除的 NmvAtlasAnchor 行走机制
  （git 历史），修正一处：嵌套符号取**相对帧**（frameIndex - keyframe.index，
  对齐 MaybeMaru `frame.getBounds(frameIndex - frame.index)`）。
- **注册解析**：exact/prefix 读 Dot-Stuff 私有 `animsMap[anim].instance.symbol.instance`
  拿实际播放符号；indices/label 是合成符号（以动画名注册进 symbolDictionary，
  keyframe.firstFrame=源帧号）直接走它 —— 四条路径统一成"查符号→走整条 timeline"。
- **应用**：offset = json 偏移(翻转修正) + scale×B；翻转态按 NMV 翻转公式镜像
  （flip 在 -B 之后：scale(-1,1)+translate(bounds.width,0) → 镜像锚 = -(B.x+B.width)）。
  B 在符号坐标系 → **scale 无关**（多K/不同谱面缩放不再错配）。
- **删除**：draw 时采样（captureNmvAnchor/nmvSampleAnchor/480 帧门控/skip-all/
  逐实例锚表）全部移除；draw() 恢复纯渲染。
- 面包屑：每个动画首次应用时打 `nmv anchorB <角色> <动画> x=.. y=.. w=.. h=..`
  （确定性值，可直接对照旧基准：bf idle 应 ≈288,-200）。

- bf/red：idle 与 sing 全部落位、无切动画瞬移、gf 不再逐拍跳动、跨场景无漂移。
