## 1. maroon 漂移 = offset 补偿**没乘 scale**（根因确定，已修）

### 1.1 推导

参考引擎（MaybeMaru）`drawAnimate` 的矩阵链：

```
matrix.identity()
matrix.translate(-bounds.x, -bounds.y)     ← 第 1 步，符号空间
prepareAnimateMatrix(matrix, camera, bounds)   ← flipX 时 scale(-1,1)+translate(bounds.width,0)
   → translate(-origin) → scale(scale.x, scale.y) → rotate → translate(screenPos + origin - offset)
```

矩阵是右乘（`M = M · T`），所以作用到点上是**先减 bounds，再 scale** ——
包围盒锚落在**符号空间**，会被角色 scale 缩放。

移植端 `drawLimb` 的 offset 是 `getScreenPosition(_point, camera).subtractPoint(offset)`，
即**屏幕空间**（scale 之后）。两端不等价，差值 = `-bounds * scale`。

`nmvApplyOffset` 此前写的是 `offset.x = jsonOffset + rect.x`（**没有乘 scale**）：
- `scale = 1` 的角色（white）恰好对 → 用户没报 white 位置问题；
- `scale ≠ 1` 的角色**每个动画按自己的包围盒比例漂**，方向和幅度各不相同 ——
  正是用户说的"每个动作都有上下左右偏移"。

数值（maroonthreat，scale 0.9，误差 = bounds × 0.1）：

| 动画 | bounds.x/y | 偏差（像素，屏幕） |
|---|---|---|
| idle | -75.8 / -95.1 | 右 7.6 / 下 9.5 |
| up | -1193.9 / -262.3 | **右 119** / 下 26 |
| left | 605.8 / -47.1 | **左 61** / 下 5 |
| right | 30.9 / -147.6 | 左 3 / 下 15 |
| down | -71.4 / -139.9 | 右 7 / 下 14 |

"up 偏右 119、left 偏左 61" —— 与用户描述完全一致。

### 1.2 改动（`source/objects/Character.hx` `nmvApplyOffset`）

```haxe
final sx = scale.x; final sy = scale.y;
final ax = (flipXr ? -(rect.x + rect.width) : rect.x) * sx;
final ay = (flipY ? -(rect.y + rect.height) : rect.y) * sy;
```

**翻转项也一起改了**（原式符号是反的）：参考引擎翻转是 `scale(-1,1)` 后
`translate(bounds.width, 0)`，点先减 bounds 再取反 → 等效符号项 = `-(bounds.x + bounds.width)`；
本端只翻不补宽。原来是 `rect.x - rect.width`，正确是 `-rect.x - rect.width`。
（未翻转的角色不受影响，所以此前没暴露。）

`nmv off` 面包屑加了 `scale=` 字段。

## 2. white 偏红 = Clipped 层的 blend 被 `filterin` 吞掉（根因确定，已修库）

### 2.1 语料证据

全语料扫 24 个 Clipper 层 / 22 个 Clipped 层，其中**8 个 Clipped 层的元素带非 normal blend**：

| 图集 | 符号 | 层 | 元素 | B |
|---|---|---|---|---|
| white | `mic hand` | Layer 3 | `_bta_asi_8` | 12 SCREEN |
| white | `down mic` | Layer_2 | `_bta_asi_23` | 12 |
| white | `up mic` | Layer 2 | `_bta_asi_30` | 12 |
| white | `right mic` | Layer 2 | `_bta_asi_33` | 12 |
| white | `mic hand copy` | Layer 3 | `_bta_asi_44` | 12 |
| maroonParasite | `mouth` / `mouth copy` | Layer 2 | `wow` | 0 ADD |
| detective | `Symbol 1 copy 9` | Layer 6 | `Symbol 41` | 0 |

**white 的 5 个 mic 正好对应 5 个唱姿** → "每个动作都有不同部位偏红" ✓

结构（`mic hand`）：

```
layer[0] 'Layer 2'  type=Clp  → ASI 位图 '7'（手形遮罩）
layer[1] 'Layer 3'  Clpb=Layer 2 → SI '_bta_asi_8' (MC, B=12 SCREEN) → ASI 位图 '8'
                                 位图 '8' 的矩阵是 4.267 倍放大 —— 红色网纹，靠遮罩裁成手形
layer[2] 'Layer 1'  → ASI 位图 '9'
```

### 2.2 根因

62 号的补丁里有这一句：

```haxe
var elemBlend = filterin ? null : blend;   // 烘焙渲染时强制 null，防双重混合
```

但 **`isMasked`（被遮罩层）也走 `filterin = true`**（`renderLayer` 里传的是
`_elemInstance(null)`，非 null 的 wrapper）→ 遮罩内容里的 blend 全部被吞成 NORMAL
→ 红色网纹以普通混合铺在手上 = "偏红"。

而且原库的遮罩贴回调用还有一处**参数错位**：

```haxe
drawLimb(layer._filterFrame, mat, coloreffect, filterin, cameras);   // cameras 塞进了 blendMode 位
```

（`drawLimb(limb, matrix, ?colorTransform, filterin, ?blendMode, ?scrollFactor, cameras)`）
运行时 `blendMode` 收到一个 `Array` → switch 走 default → 等于 NORMAL，所以不崩但也不混。

### 2.3 改动（`patches/flxanimate-blend-masked.patch`，改的是 haxelib 全局库）

| 位置 | 改动 |
|---|---|
| `parseElement` 头部 | 新增 `selfBlend`（元素**自身**混合，不受 filterin 影响）；`elemBlend` 改为 `selfBlend != null ? selfBlend : (filterin ? null : blend)`；新增 `pasteBlend = selfBlend ?? blend` |
| `toBitmap \|\| isMasker` 分支贴回 | `drawLimb(..., pasteBlend, null, cameras)`（顺带修参数错位） |
| `toBitmap` 分支贴回 | 同上 |
| `isMasker` 分支贴回 | `drawLimb(..., maskerBlend(symbol, layer), null, cameras)` |
| 新增 `maskerBlend(symbol, masker)` / `frameFirstBlend(frame)` | Clipper 层贴回时取"被它遮罩那一层"的第一个非 NORMAL blend |

**为什么不把 blend 放进中间渲染**：Dot-Stuff 的遮罩是
「clipped 内容先渲进 `maskCamera` → 与 clipper 层合成到一张离屏 bitmap → 整块贴回主画面」，
中间那步的混合对象是空白离屏 canvas，混了没意义；真正的混合点在最后贴回。

**兼容性**：默认路径（无遮罩 / 无 blend）行为不变；原来是"blend 收到 Array → NORMAL"，
现在无 masked 兄弟层时 `maskerBlend` 返回 null → 同样 NORMAL。

## 3. sussus-toogus：walkers 走在桌子前面（z-order）

`legacy/songs/sussus-toogus/script.hx` 在 **`onLoad`** 里建 6 个 `AmongWalker` 并
`stage.add(walker)`，`zIndex = i+2`（2..7）；舞台 `tn`（桌子）zIndex=10。
脚本在 `onCreatePost` 里主动调 `refreshZ()`。

移植端 `script.set('stage', FlxG.state)`（平铺无 stage 组），`sortStageZ()` 只排
`nmvStageZBound` 边界内 —— 而 bound 在**角色组 add 完**就定死了，walkers 在界外
→ 不参与排序 → 保持插入序（都在桌子之后 add）→ **画在桌子前面**。

**改动**（`PlayState.refreshZ`）：脚本主动调用（group == null）时先把
`nmvStageZBound = FlxG.state.members.length` 再排 —— 等价于 NMV 的
`refreshZ(stage)`（stage 组含脚本 onLoad 加的一切）。`onCreatePost` 里这次调用之后
才 add 的 saxguy 仍不受影响，与 NMV 时序一致。

## 4. sussus-toogus：walkers 偏下

`AmongWalker.reloadAtlas()` 原版是 `updateHitbox(); y = savedHeight - height;` ——
NMV 继承 Bopper（sparrow），`updateHitbox()` 当场把 `height` 填成帧高。

移植端走 flxanimate：`height` 要等**第一次 draw** 里 `_flashRect.height` 才算出来，
构造期读到 0 → `y = savedHeight` → 整只往下掉一个身高 = "偏下"。

**改动**：`updateHitbox()` 后置 `yAligned = false`，在 `update()` 里
`if (!yAligned && height > 1) { y = savedHeight - height; yAligned = true; }`。

## 5. modchart P0 + P1 落地

新增 `source/nmv/modchart/`：

| 文件 | 内容 |
|---|---|
| `Modifier.hx` | `ModifierType` / `ModifierOrder` 枚举 + 基类（`getPos` / `updateNote` / `updateReceptor` / 子模 / 排序） |
| `NoteModifier.hx` | `NOTE_MOD` 标记 |
| `SubModifier.hx` | 同名子模（`xmod0..`），order=LAST |
| `ModManager.hx` | 注册表 + `activeMods[per lane]` + **绝对布局**（`getCenterX`/`getStrumX`/`getBaseX`/`getBaseY`）+ **delta 管线**（`getPosDelta`）+ `applyObjectMods` + `update` |

`nmv/utils/ModManagerCompat.hx` 改造：
- 新增 `core:nmv.modchart.ModManager`（真内核），`getPosDelta` 委托；
- 位置函数委托给内核静态函数（单人唱/多人唱共用一套公式）；
- `registerMod` 遇到真的 `Modifier` 实例会转登记进内核 —— P2 补子类后 delta 自动生效。

**关键设计（63 号 §4 的 P1）**：
`getPosDelta = getPos(...) - 基准`。`activeMods` 为空时**直接返回池化的 (0,0,0)**，
不进链、不建 Vector3 → **默认零视觉变化**，可安全合入。
没有接管 x/y，也没有 `centerOrigin/centerOffsets`（那两笔会撕裂 sustain 的 clipRect）。

**未做（P2/P3）**：具体 modifier 子类（X/Drunk/Beat/Scale/Alpha/Reverse/Bounce…）与
events 时间线（`queueEase` 真动画）。语料 218 个谱面零 `mods` 数据、4 首歌的
`modchart(step)` 只是镜头缩放且无调用点，所以按 63 号建议停在骨架。
