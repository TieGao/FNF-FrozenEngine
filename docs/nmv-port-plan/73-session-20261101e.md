## 3. Freeplay 对 NMVMODS 谱面的支持（用户报的"还没完全支持"）

### 症状

实机 `crash/latest.log`：

```
FreeplayState.hx:2058: ERROR: Chart file not found: victory-hard
FreeplayState.hx:2058: ERROR: Chart file not found: heartbeat-hard
```

Freeplay 里 NMV 包的歌**能进游戏**（走 `Song.getChart` → `findNmvChart`），但：
- 试听（toolbar 播放键）直接抛 `Chart file not found`；
- 卡片拿不到 BPM / 时长 / 键数 / 评级（`SongInfoParser` 找不到谱面 → `getDefaultInfo()`）；
- 难度条显示 Easy/Normal/Hard，实际盘上只有 `normal.json`。

### 根因

谱面路径解析有**三套各自为政的候选**，只有 `Song.getChart` 那套认识 NMV 布局
（`<包根>/songs/<歌>/data/<难度>.json`，包根相对、没有 `shared/data` 前缀）：

| 位置 | 原候选 |
|---|---|
| `Song.getChart` | `Paths.json` + `findNmvChart` ✅ |
| `FreeplayState.togglePlaySong` 试听前置检查 | `Paths.modsJson` / `Paths.json` ❌ |
| `SongInfoParser.resolveChartPath` | mods/data、modsJson、`Paths.json`、assets/data、assets/shared/data ❌ |

`Paths.json('<歌>/<歌>')` 在 NMV 包根下只会拼出 `<root>/<歌>/data/<歌>.json` /
`<root>/data/<歌>/<歌>.json`，**都不是** NMV 的 `songs/<歌>/data/normal.json`。

### 修法

1. `Song.findChartPath(folder, song)`（新，`#if sys`）：**唯一**的谱面路径解析入口 ——
   `Paths.json`（内部已按 mods → 内容包 → assets 探）→ `findNmvChart` → `assets/data` →
   `assets/shared/data`，存在才返回。
2. `FreeplayState.togglePlaySong` 的前置检查改调它（不再自己拼路径）。
3. `SongInfoParser.resolveChartPath` 在 `#if sys` 下直接委托给它（`#else` 保留原分支给非 sys）。
4. `Song.findNmvChart` 的资源根改为**先看 `Paths.currentContentRoot`**（是 NMV 根就用它），
   再退回 `NMVContentData.currentMod` —— Freeplay 试听 / `SongInfoParser` 都只设前者。

### 难度表

`NMVContentData.collectDifficulties(mod)`（新）：扫包内 `songs/<歌>/data/*.json` 与
`songs/<歌>/*.json`，文件名即难度名（`normal` → `Normal`），剔掉 `events*` / `song` /
`other` / `meta*` / `*-old`；Normal 排最前（`Difficulty` 下标 0 = Freeplay 默认档）。
`readWeek()` 用它填 `difficulties`（原来是 `''` → 退回 Easy/Normal/Hard）。
按 mod 缓存，进程内只扫一次。

配套：`LoadReplaySubState` 把回放里的难度下标**夹回当前难度表**——
旧回放记的 `Hard` 在新表（只有 `Normal`）里匹配不到，关键词兜底会给出越界下标，
`Difficulty.getFilePath` 随后取到 null。

## 4. 复查结论：无按名字特化

扫过的判据全部是**结构性**的：

| 判据 | 用在哪 |
|---|---|
| 内容根路径含 `/NMVMODS/`（`Paths.isNmvContentRoot`） | 图集锚点补偿、NMV 资源候选、`Character.nmvContentChar` |
| `NMVContentData.currentMod != null` | 脚本宿主接线、per-lane note 管线、事件合并 |
| `SONG.lanes > 2` | 多 playfield 分支 |
| 字段/类型存在性（`Std.isOfType`、`Reflect.hasField`） | HScript 兼容面 |
| 图集 json 结构（`AN.SN` 主符号、帧标签、indices、`SI.B` 混合模式） | flxanimate 语义 |

`curCharacter == 'xxx'` / `songName == 'xxx'` 这类在 NMV 移植代码里**零命中**；
搜到的三处（`Character` 的 `gf-` 前缀、`GameOverSubstate` 的 `pico-dead`/`nene`）都是
移植前就有的 FE 原版逻辑。

唯一"调出来的常数"是 `AmongWalker.FOOT_BIAS`（脚底对齐微调），作用对象是**所有** walker，
不是某个角色；用户实测值，集中一个常量，已注释说明。
