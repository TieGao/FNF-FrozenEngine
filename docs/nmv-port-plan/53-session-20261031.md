## 1. events.json 从来没被加载（缺 event 的根因）

`Song.findNmvChart('danger', 'events')`：`events` 无横杠 → difficulty 落回 `'normal'`
→ 第一候选命中 `songs/danger/data/normal.json`。**事件图表被加载成 note 谱**，
真正的 `data/events.json`（vanilla 旧事件格式）从未被读。
日志佐证：`converting chart events with format nmv2`（events.json 根本没有 format 字段，
normal.json 才有）。

修：`findNmvChart` 特判 `events`/`events-*`，候选 `data/events-<变体>.json` →
`data/events.json` → `events.json`。

### 双来源合并 + 去重
NMV 原版 `getEventsDirect` = events.json + SONG.events **两个来源都读**。
实测这批包 double-trouble/voting-time 的内嵌 events 与 events.json 内容**逐条相同**
（编辑器双导出）。FE 原规则"内嵌非空跳过外置"会丢掉这批歌的 events.json 事件。
修：NMV 语料（`NMVContentData.currentMod != null`）两个来源都合并，
按 `(时间, 事件, 值1, 值2)` 去重（`eventDuplicatedInChart`）。
FE 自己的谱保持原规则不变。

## 2. Finale 崩溃链（VarTween alpha）

崩溃栈：VarTween.setStartValues → `The object does not have the property "alpha"`。
链路：
1. `finalem.hx` onCreatePost 在 `playHUD.timeBar.visible`（116 行）断掉
   —— PlayHUDShim 缺 `timeBar` getter；
2. → 131 行 `finaleDarkFG = new FlxSprite(...)` 没执行，保持 null；
3. → onSongStart:206 `FlxTween.tween(finaleDarkFG /*null*/, {alpha: 0}, 9.6)`
   → VarTween delay 结束读 alpha → 抛错 → 崩溃。

修：PlayHUDShim 补面（全包扫描 `playHUD.<x>` 用面）：
timeBar/timeTxt/healthLerp（get 每 Frame 向 PlayState.health 收敛 0.15，NMV PsychHUD 同参）/members/add/insert（转发 uiGroup）/
updateIconPos/updateIconScale/updateIconAnimation（可写开关）/updateIconsPosition()（空实现）/ratingPrefix。
另：FE PlayState 补 `healthBounds:FlxBounds<Float> = (0.0, 2.0)`（finaleUI:26 读
`game.healthBounds.min/max`；NMV PlayState 同名同值）。

## 3. 锚点补偿重做（Danger 角色偏移 + 换角色瞬移）

旧实现"首帧绘制实测"三个不稳定源（面包屑实证）：
- 换实例（Change Character）重新首帧采样 → 同角色两个值（danger 76,343 → -5,-190）；
- 首帧不碰时间轴包围盒角的角色量出全错值（blackparasite -2074、maroonParasite -582）；
- relativeX 是屏幕空间且 limbOnScreen 有裁剪/zoom 畸变。

NMV 的 flixel-animate 以「整条时间轴包围盒左上角」定锚（Timeline.getWholeBounds）。
新实现 `nmv/utils/NmvAtlasAnchor.hx`：从已解析的 FlxAnimate 对象树确定性递归计算
（逐根帧、逐可见层、嵌套符号按 Loop/PlayOnce/SingleFrame 语义取当帧、位图四角矩阵变换、
按 符号#帧 记忆化、深度护栏），**不渲染**。Character.captureNmvAnchor 优先级：
同图集缓存（键=image 路径，跨实例复用）→ 确定性计算（乘 scale 后应用）→ 首帧实测兜底。
**验证基准**：bf 应 ≈ (288,-200)、gf ≈ (-147,-333)、black ≈ (-4,-3)（旧面包屑的正确值），
新面包屑前缀 `nmv anchor calc`。

## 4. NMV 原生事件缺口（镜头事件偏移的主嫌之一）

NMV 引擎 triggerEvent 原生分支里 FE 没有的名字（全包使用数）：
`Set Cam Zoom`(25，绝对值直设 defaultCamZoom)、`Camera Zoom`(59，乘数+可选 tween、
NMV 硬编码 circOut)、`Set Cam Pos`(12，改角色相机偏移)、`HUD Fade`(12，camHUD alpha 补间)。
`Camera Zoom Chain`/`Screen Shake Chain`/`Change Noteskin` 全包 0 使用，未移植。
已作为 case 加进 FE triggerEvent（这些名字只出现在 NMV 包事件里，无碰撞）；
switch 落到底保证 stagesFunc/onEvent 广播与 NMV 一致（原生处理后仍广播脚本）。

**注意**：events.json 修复前，这批事件根本没触发过；用户看到的"偏左上"来自
double-trouble 内嵌 camTween（世界坐标 1650,925@zoom0.45 之类）。修复后如仍有偏移，
按 camTween 逐条对 NMV 世界坐标核对（双修后复测重点）。

## 10. 批次 3：锚点补偿第三次重做（包围盒模型推翻）

用户反馈"很多角色仍偏移"（旧构建）。harness 锚点审计把全部 ~90 个图集的确定性
计算值打出来对照后，**推翻了"整条时间轴包围盒定锚"模型**：

- 实测正确值 vs 确定性计算：bf 288,-200 vs -212,-201（X 不符）、gf -147,-333 vs
  265,52（全不符）——模型错了。
- 复查 NMV flixel-animate：`applyStageMatrix` **默认 false 且引擎源码从不开启**
  → `prepareDrawMatrix` 的 bounds 平移根本不走 → **两边渲染数学本就一致**。
- 补偿的真实语义：旧"首绘帧内容 min"把内容 bbox 左上角钉在逻辑位上
  （draw = x - offset + contentMin(frame) - contentMin(idle0)），实测值即由此而来。
- 新修三缺陷：①同图集静态缓存（`Character.nmvAnchorCache`，键 = image 路径，
  值与实例 offset 无关）修换实例瞬移；②**idle@0 帧门控**（idle/danceLeft/danceRight
  + curFrame==0）修首绘离群帧（blackparasite -2074），480 帧超时退回首绘采样；
  ③补 `viewMargin`（fork 的 worldToView = world - scroll - viewMargin，zoom 折进
  margin，旧公式 zoom≠1 时被污染——danger defaultZoom=2 的场景受影响）。
- NmvAtlasAnchor.hx 与 harness 审计段已删除；面包屑改为 `nmv anchor idle|timeout <名>`。
- 下轮实测：对照旧正确值（bf≈288,-200 / gf≈-147,-333 / black≈-4,-3），parasite 类
  应变为 idle 帧的合理值；danger 换实例不应再变值。
