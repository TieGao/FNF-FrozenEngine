`maroon w=5 h=3` 是走错帧数的铁证。

## 2. 根因（读两边库源码逐行比对，5 处）

### 2a. 动画→符号解析用 Reflect 读 Map（致命）

`FlxAnim.animsMap` 是 `Map<String, SymbolStuff>`，hxcpp 下是原生 StringMap；
`Reflect.hasField/animsMap[name]` 永远取不到键 → exact / prefix / indices / 帧标签
四条注册路径**全部解析失败**。只有"动画名恰好等于字典里的符号名"的少数角色（charles、
maroon）靠兜底分支蒙对。

修：`@:privateAccess atlas.anim.animsMap.get(animName)` → `stuff.instance.symbol.name`
（四条路径都往 animsMap 写，值就是符号字典的键）。

### 2b. `FlxTimeline.length` 是**层数**，不是帧数

Dot-Stuff：`get_length() return _layers.length`；帧数是 `totalFrames`。
旧代码 `for (f in 0...sym.timeline.length)` 只走前 1~3 帧 → maroon 的 `w=5 h=3`。

### 2c. 嵌套符号引用读错字段

Dot-Stuff 的 `FlxElement.symbol` 是 `SymbolParameters`：
`instance` = MovieClip 实例名，**`name` 才是被引用符号名**（`parseElement` 里
`symbolDictionary.get(instance.symbol.name)`、`FlxElement.updateRender` 里
`dictionary.exists(symbol.name)` 都证明了这点）。旧代码读 `el.symbol.instance` → 嵌套符号全查不到。

### 2d. 锚不该乘 scale

openfl `Matrix.translate` 是**裸加**（`tx += dx`，不乘 a/b/c/d）。MaybeMaru 的
`matrix.translate(-bounds.x,-bounds.y)` 在 `scale(scale.x)` 之前、且因为裸加，锚落在
**屏幕空间**、与 scale 无关。旧代码 `scale.x * ax` → 缩放角色（0.9 / 多K）跨场景漂移。

### 2e. 翻转锚符号错

推导（两边都是裸加）：
```
NMV  : x = ±scale·p + (-bx [+ bw 当翻转]) + 屏幕位置 - json偏移
本端 : x = ±scale·p + 屏幕位置 - offset
⇒ offset = json偏移 + bx [- bw 当翻转]
```
翻转项来自 MaybeMaru `prepareAnimateMatrix`：`matrix.scale(-1,1); matrix.translate(bounds.width,0)`
（Dot-Stuff 只翻不补宽）。旧代码写 `-(bx+bw)`，方向正好相反。

另：**json 偏移不随翻转镜像**。NMV 的 `correctFlippedOffsets` 默认 false 且角色侧从未开启
（`FunkinSprite.hx:56` / `Character.hx:204` 只设 `scalableOffsets`），所以旧代码那段
`frameWidth - baseFrameWidth - daOffset[0]` 的镜像修正与 NMV 不一致，已从锚点路径移除
（FE 原生图集路径保持原样）。

## 3. 新实现

- 删除 `source/nmv/utils/NmvAtlasBounds.hx`。
- 新增 `source/nmv/utils/NmvAtlasAnchor.hx`：MaybeMaru `Timeline.getWholeBounds` 的逐行移植。
  - 遍历 `timeline.totalFrames` 的每一帧 → 每层（跳过 `!visible`）→ `layer.get(f)` 取关键帧
    → 每个元素；
  - 位图元素：`rect(0,0,fr.frame.w,fr.frame.h)` 再 `translate(fr.offset)`（等价
    `FlxFrame.prepareBlitMatrix(false)`），然后过元素矩阵（`el.matrix` + `translate(el.x,el.y)`，
    与 Dot-Stuff `parseElement` 一致）；
  - 嵌套符号：`firstFrame + (帧号 - kf.index)`，Loop 取模 / PlayOnce 截断 / SingleFrame 首帧，
    递归后过元素矩阵；
  - `符号键#帧号` 记忆化（键带 `location`，因为字典会把 name 截成末段）+ 深度护栏 32；
    结果按 `图集路径|动画名` 跨实例缓存。
- `Character.nmvApplyOffset`：`offset = json偏移 + (bx - 翻转?bw:0, by - flipY?bh:0)`，不再乘 scale。
- 面包屑改为每条动画一次：`nmv bounds <图集>|<动画> sym=<符号> frames=<n> x= y= w= h=`，
  解析不出时打 `sym=<none>`。

# 追加（同日 11:xx）：包围盒改成「按符号」而不是「按动画」

## 症状

重建后 `nmv bounds` 全部打得出来（包围盒计算本身已对），但用户仍报：
bf / b-ghost / gf 小偏移、meltdown 里 red 特别明显、green 部分不对、ejected 三者明显偏下。

## 根因：用错了时间线（子集 vs 整符号）

MaybeMaru 三条注册路径**都把 `anim.timeline` 设成被引用符号自己的时间线**：

- `addBySymbol(name, symbolName)` → `anim.timeline = symbol.timeline`（FlxAnimateController:222）
- `addBySymbolIndices(name, symbolName, indices)` → 同样 `= symbol.timeline`（:255），
  **indices 只决定播哪几帧，不影响 `_bounds`**
- `addByFrameLabel` → `anim.timeline = usedTimeline`（根时间线）

而移植端的 `safeAddBySymbolIndices` 造的是**包装符号**（键 `<源符号>#<动画>`，时间线只含选中的
那几帧），于是我们算的是"这几帧的并集"，NMV 算的是"整个符号"。

实测差值（离线复算，同一图集）：

| 角色/动画 | 子集（旧） | 整符号（NMV） | Δ |
|---|---|---|---|
| red `idle-loop`（meltdown） | 169, 462 | 101, 431 | **-68, -31** |
| green crewmate `idle` | 243, 122 | -28, -8 | -271, **-130** |
| green `danceRight`（Symbol 1） | -537, -177 | -822, -313 | -285, **-136** |
| bf-ghost `idle` | -2, 36 | -27, -42 | -25, **-78** |
| bf `singLEFT`（帧标签） | -212, -207 | -214, -271 | -2, **-64** |
| gf `danceRight` | -149, -333 | -149, -334 | 0, -1 |

`-loop` 变体（meltdown 全用这套）、green 的两个角色、bf-ghost、bf 的帧标签动画全都命中，
与用户报的现象一致。

## 修法

`NmvAtlasAnchor.resolveSymbol`：拿到 animsMap 里的符号名后，若含 `#` 就**拆回 `#` 前的源符号**
（源符号不存在才保留包装本身）；缓存键同时改成 `图集|符号` —— 同一符号的所有动画共用一个包围盒，
切动画不再跳位。

## 未解决：ejected 三者「偏下」不是锚点

那三位的注册是 `exact`（整符号），锚点已经是 NMV 原值，改动前后不变：

三个角色同时偏下、且锚点数值已与原版一致 → 更可能是 **Ejected 舞台的镜头/站位**（zoom、

# 追加（13:4x）：包装符号键污染前缀匹配 + 零件帧映射差异

## A. 包装符号的字典键会污染 `addBySymbol` 的前缀匹配（"组件混用 / 播放串台"）

移植端的 indices / 帧标签动画走 `safeAddBySymbolIndices`，注册键原本是
`<源符号>#<动画>` —— **以源符号名开头**。而 Dot-Stuff 的 `FlxAnim.addBySymbol` 是：

```haxe
for (name in symbolDictionary.keys())
    if (startsWith(name, SymbolName)) { params.symbol.name = name; break; }
```

遍历整个字典取**第一个前缀命中**，Map 顺序不保证。于是 `addBySymbol('singLEFT', 'left')`
可能先撞上之前注册的包装键 `left#singLEFT`（只含别的动画选中的几帧）→ 动画播成另一个
姿势的子集，零件（手/护目镜）跟着串 → 就是"动作不同会有不同的组件，组件混用了"。

修：包装键改成 `@<源符号>@<动画>`，以 `@` 开头，永远不进前缀匹配。
`NmvAtlasAnchor.resolveSymbol` 同步解析新格式（拆回 `@` 之间的源符号）。

## B. 新增面包屑

- `char[<角色>] bind <动画> -> <符号名>`：每个动画实际绑定的符号。下轮日志能直接看出
  有没有动画绑到包装/别的符号上。
- `nmv off ... flip=<bool> bw=<包围盒宽> json=.. anchor=.. -> ..`：翻转角色的锚点里含
  `-bw` 项，现在 bw 直接可见，一眼能对账"是不是整体偏了一个身位宽"。

## C. 零件帧映射：两个库的嵌套帧公式本来就不一样

`whitedk` 的 `idle_w`（14 帧）第 0 层引用 `mic hand`（**5 帧**），最后一个关键帧
`I=8 DU=6` → 相对帧 0..5 → 第 5 帧回卷到 0。若第 0 帧的手和第 4 帧不是同一只手，
就是"idle 末尾用了别的手"。

两个库对嵌套符号的帧映射**公式不同**：

- Dot-Stuff（本端，`FlxElement.updateRender`）：`curFF = (层帧 - 关键帧index) + firstFrame`，再 `% length`
- MaybeMaru（NMV，`SymbolInstance.getFrameIndex`）：`firstFrame + (index - frameIndex)`，
  其中 `index` 是元素在帧里的序号（通常 0）、`frameIndex` 是**时间线绝对帧**

所以同一份数据在两边算出的零件帧本来就可能不同 —— 这是"零件混用"的机制来源。
要对齐只能把渲染路径接管（例如按 NMV 公式预烘焙成逐帧 SF 关键帧），属于改渲染的大动作，
先确认现象再动。

## D. suspect 的 pico「整体偏左」

- 锚点很小（`idle anchor=-12,-1`），不是偏移链路的问题
- `positionArray` 只应用一次（`startCharacterPos`，与 NMV `CharacterGroup.startPos` 同款）
- 所以整体偏左来自**舞台基准位置**（`BF_X` / 舞台 json），不在本轮范围
- 那个"炸一下"的动作是 `singLEFT`：json 自带 `offsets=[-575,-115]`（作者写的），NMV 也照用

# 追加（17:xx）：注册优先级反了（符号 vs 帧标签）+ 遮罩语义

## A. 真根因：NMV 是「帧标签优先」，移植端是「符号优先」

`white` / `whitedk` 的 json `name` 与**根时间线的帧标签完全同名**：

```
white   根 '!!!'  标签: idle, down, up, right, left, alUp, alDown
whitedk 根 '!!!!' 标签: idle_w, down_w, up_w, left_w, right_w
```

NMV `FunkinSprite.addAnimByPrefix` 的顺序是 **帧标签 → 符号 → 前缀**：

```haxe
if (anim.findFrameLabelIndices(prefix).length > 0) addByFrameLabel(...)   // ①
else if (checkLibraryForSymbol(library, prefix)) addBySymbol(...)         // ②
```

走帧标签时 `anim.timeline = usedTimeline`（**根时间线**）→ 同一角色所有姿势共用根时间线的
包围盒 → 位置稳定。移植端把 ② 放在 ① 前面（旧注释的理由是"同名包装会覆盖真符号导致递归
闪退"，而现在的 safe 包装键是 `@<符号>@<动画>`，不写既有键，这个理由已不成立），于是每个
姿势走自己的符号、各算一个包围盒 → **逐姿势位移 = "到处飘"**。

实测：white 的姿势包围盒 `idle -593` / `right -331` / `down -240` / `left -362` / `up -361`，
逐符号对齐时身体落点相差 ~185px；改成根时间线后全部共用 `(2,-15)`（white）/
`(-631,-89)`（whitedk），不再跳。

修：注册链改成 `indices → 帧标签 → 精确符号 → 帧标签兜底 → 前缀`（`indices` 仍排第一，
因为 gf 的 danceLeft/danceRight 靠 indices 切分同一符号，走标签会合成一条）。

影响面：1042 个动画里有 **194 个**（符号与标签同名且无 indices）会从符号切到标签，涉及
charles / greythreat / bf-fall / picoweird / maroonplayable* / pinkplayable / doubleTrouble /
redmungusp / white / whitedk 等 —— 这是 NMV 的原语义。

## B. 补上遮罩语义（Clipper / Clipped）

NMV：Clipper 层 `visible=false`、不进包围盒；Clipped 层与遮罩层**求交**。
移植端原来两者都按普通层累加，被遮罩的零件按"未裁切"撑大包围盒。

修：`NmvAtlasAnchor.frameBounds` 里跳过 Clipper 层、Clipped 层与按层名找到的遮罩层求交。
全库 106 个图集里 7 个有遮罩层：white(10)、danger(14)、bfdefeatgameovers(11)、
maroonParasite(4)、detective(2)、bfRun(1)、black(1)。

## C. whitedk「最后几帧扭曲」的机制

`idle_w` 第 0 层的最后一个关键帧 `I=8 DU=6`，零件（`knife` / `mic hand` / `idle bod`）
在 JSON 里没有 FF/LP → 按 Loop 处理，相对帧 0..5 依次推进：

```
idle 末尾：knife f0(143x197) → f5(192x289)
           idle bod f0(240x319) → f5(280x267)
           halo f0(302x185) → f2(373x344)
```

零件跳到"别的姿势的帧" → 看起来就是最后几帧扭曲。

两个库对这一项的公式是一致的（`firstFrame + (帧号 - 关键帧起点)`），所以 NMV 按同一份数据
也会这样；Animate 本体则是"循环零件的播放头跟时间线连续走、不按关键帧重置"，这才是原作者
在 Animate 里看到的正常效果。要复现 Animate 语义只能接管渲染（把嵌套帧改成绝对帧），
属于改渲染路径，待确认后再动。

# 追加（17:1x）：血条颜色跟随"当前角色"

`reloadHealthBarColors()` 原来只在 `create()` 和 `'Change Character'` 事件里调。NMV 舞台脚本
常用 `setProperty('dad', ...)` / HUD shim 直接换角色（甚至换整条血条），不走那个事件 →
血条停在旧颜色或默认色，表现就是"有的血条读不到颜色"。

修：`PlayState.update` 里做**变更检测**（角色实例引用 + `curCharacter` 名字，两者都记），
一变就重刷。判据是"显示的角色是否变了"，不是角色名白名单。

同时 `reloadHealthBarColors()` 里加一条面包屑，下次日志能直接看到实际用的颜色：

```
hud bar colors dad=maroon:82,35,47 bf=bfpolusblow:49,176,209
```

语料侧核对过：192 个角色 json 里 168 个只写单值 `healthbar_colour`（ARGB int）、23 个写
`healthbar_colors` 数组、1 个（`securitydlc/.../purple.json`）**JSON 本身带尾逗号解析失败**；
5 个是作者就设成灰/黑的（bf-dark / doubleTroubleGf / doubleTroubleRed / green-dark / nenelobby）。
